# Datasheet Reader 产品与开发计划

方案日期：2026-10-29。状态：阶段 1 已通过云环境自动及浏览器测试，等待 Windows 实机验收；后续阶段仍为规划，尚未实现。

## 1. 用户、目标与需求补充

主要用户是使用 Windows 的硬件初学工程师，熟悉少量 Python，关注 BUCK、LDO、MOSFET、高边开关、MCU 与电动自行车电机控制器。优先实现可靠的“阅读—选区—翻译—解释—追问—回看原文”闭环。

需要补充的重要需求：

| 容易遗漏的需求 | 处理决定 |
| --- | --- |
| 参数查找 | 第一版提供文字搜索、结果跳转与页码导航；结构化参数提取后续再做 |
| 手册身份及修订版 | 按文件内容摘要区分文档，显示文件名；可记录厂商、器件、修订信息，不能仅凭文件名合并 |
| 页码歧义 | 引用统一使用从 1 开始的 PDF 页序号；印刷页码或 PDF 标签如能识别则另列，不混用 |
| 复制乱码、扫描 PDF、多栏阅读顺序 | 检测无文字或异常选区，提示限制；允许预览并修正待发送文字，保留原始选区以便审计 |
| 表格、脚注、上下标 | 不把跨列选区拼接为确定含义；缺少表头、单位或脚注时提示扩大选区，不凭空补齐 |
| 文件边界 | 第一版以单个活动文档为主，支持切换；损坏、加密、非 PDF 或超限文件给出明确错误，不尝试破解 |
| 误操作与数据保存 | 原件只读；应用副本与后续笔记独立存储；移除副本需确认，不能删除原件 |
| 隐私 | AI 请求前展示发送范围；不默认传整份 PDF；密钥、选区及回答不进入普通日志 |
| 中断与费用 | 显示等待、取消、重试及错误；限制输入和输出长度，避免重复计费；失败不自动无限重试 |
| 长期维护 | 固定依赖版本、保留样例评测、记录模型与提示词版本；更新后跑回归检查 |
| 离线与可访问性 | 无网可阅读；支持键盘翻页、可调整侧栏字号；云端 AI 明确提示需联网 |

默认优先支持 Windows 11 64 位、Edge/Chrome，以及带文字层的英文 PDF。Windows 10 或其他系统不先承诺支持。第一阶段记录实际测试的系统、浏览器、硬件及 PDF 范围。

## 2. 版本范围

**第一版 v0.1 = 阶段 1～4 全部验收通过。** 单独完成 PDF 阅读器不代表完成智能翻译功能。

| 必须具备 | 后续扩展 |
| --- | --- |
| 导入、阅读、翻页、缩放、页码跳转、文字搜索 | 最近阅读、目录增强、书签与笔记 |
| 选区捕获、原文预览、页码及定位 | 跨页复杂选区、框选表格、OCR |
| 专业翻译、原文与译文并排 | 整页翻译、全文后台翻译、双语导出 |
| 参数保真检查及异常提示 | 更强的公式、表格结构识别与参数对比 |
| 术语解释、选区内连续追问 | 全文检索问答、跨文档比较、学习卡片 |
| 可核对的引用、范围不足提示 | 检索增强生成与多页证据聚合 |
| AI 安全设置、费用提示、错误处理 | 本地模型、翻译缓存、桌面安装包 |

第一版的“保留排版”指始终显示原始 PDF，不承诺在原位置用中文替换英文。右侧中文允许换行，并保留公式及原始片段供核对。扫描件可尝试显示，但无文字层时不提供选词翻译。

## 3. 推荐架构与取舍

### 3.1 运行方式

浏览器（React＋PDF.js 阅读区＋中文侧栏） → 本机 FastAPI 服务 → PDF 应用副本 / AI 适配层；后续由同一本机服务访问 SQLite。

服务仅监听 127.0.0.1，不开放局域网。开发环境由 Vite 将 `/api` 转发到 FastAPI；PDF.js 及 worker 使用锁定版本的本地依赖。浏览器不直接接触密钥。根据第一阶段要求，界面采用 React 与 JavaScript，暂不增加 TypeScript、桌面壳或其他前端状态框架。

选择 PDF.js 是因为 PDF 渲染和文字层已有成熟方案；选择 Python 服务方便用户逐步理解文件操作、接口与 AI 调用。Streamlit 适合快速数据演示，但精细的选区、页码和 PDF 联动需要额外组件；Qt 桌面方案涉及界面绑定与打包，因此暂不采用。后续只有在浏览器方案确实不满足需要时，再评估桌面外壳。

不在第一版引入 OCR、向量数据库、LangChain 或本地大模型。PDF 文本先利用 PDF.js 文字层，后续全文索引再评估额外 PDF 解析库及其许可证，不提前增加依赖。

### 3.2 模块边界

- 阅读器：渲染、搜索、选区与页面坐标转换。
- 文档服务：验证 PDF、分配文档 ID、存储只读副本、按授权 ID 提供文件，拒绝任意文件路径读取。
- AI 服务：统一翻译、解释和追问请求，封装供应商接口、超时、取消及限流处理。
- 保真检查：识别原文中的数值、范围、单位、关系符号、公式及条件，检查输出；不通过时返回警告或阻止标记为已校验。
- 引用服务：使用真实选区记录生成来源，校验模型返回的引用 ID，拒绝不存在的页码或证据。
- 设置与存储：非敏感配置、系统密钥存储；后续 SQLite 保存笔记与缓存。

### 3.3 数据与文件

程序目录与用户数据分离。计划把应用数据放在 Windows 用户目录下的 LocalAppData/DatasheetReader，包含应用 PDF 副本、非敏感设置，后续增加 SQLite。开发数据放入明确忽略的本地目录，不能提交手册或密钥。

选区记录至少包含：文档摘要/ID、文件名、PDF 页序号、页面内归一化矩形列表、原始文字、发送前修订文字（如有）。多行选区可有多个矩形。引用优先定位原始选区；缩放后坐标仍应对应正确位置。

AI 结果记录模型、提示词版本、来源片段 ID、处理时间和校验状态。第一版会话内容默认仅在内存保留，关闭后不承诺恢复；持久化笔记与缓存到后续阶段再明确提供。

### 3.4 翻译与证据约束

1. 发送前展示原文与页码，用户可发现 PDF 提取错误；选区内容作为数据处理，不能让文档中的指令改变程序行为。
2. 忠实译文与通俗解释分栏或分区；术语表明确区分 absolute maximum ratings、recommended operating conditions、typical、guaranteed 等。
3. 保留数字字面值、正负号、范围、不等号、上下标、单位与公式，不默认换算单位。条件包括温度、电压、电流、频率、占空比、测试电路及脚注限定。
4. 先抽取并保护可识别的参数片段，结合结构化输出和输出后检查。对同值不同位置、条件和参数之间的关联仍需样例评测；不能宣称自动校验能数学上保证译文正确。
5. 识别到遗漏、替换、损坏或条件不清时，展示具体差异与原文，标记“需人工核对”；不以正常成功状态掩盖。无法可靠处理的公式显示原文并说明限制。
6. 选区问答只对实际提供的证据作文档结论。提问超出选区时提示提供相关页；通用原理可回答但标注为通用知识，不附虚构文档依据。
7. 来源链接由程序使用真实记录构造，模型不能随意生成文档页码。点击返回相同文档及页序号，并尽可能高亮片段。

## 4. 开发阶段与验收

每阶段流程：实现最小功能 → 自动检查 → 实际操作演示 → 记录限制 → 用户验收。重要技术变更先解释原因。下列工期为专注开发工作日粗估，包含调试，不是交付承诺；用户学习、测试反馈和模型评测会延长日历时间。

### 阶段 0：方案（本轮，约 0.5～1 天）

交付 README 与本计划；不创建应用代码、不安装额外依赖、不调用付费 AI。

验收：需求、架构、范围、风险、成本和各阶段标准齐全；明确第一阶段边界并等待用户确认。

### 阶段 1：最小本地 PDF 阅读器（约 3～5 天）

任务顺序：

1. 建立 Python 虚拟环境、固定依赖及简单目录结构，加入本地运行与测试说明。
2. 建立 FastAPI 本地服务与 PDF.js 页面，提供一条 Windows 启动路径；开发时允许终端启动。
3. 导入本地 PDF 并创建副本，完成翻页、缩放和跳页。本轮确认范围不含文内搜索，搜索功能延期评估。
4. 捕获当前单页文字选区，在侧栏显示英文、页序号，能返回定位；不接 AI。
5. 加入文件错误处理、导入限制和只读原件保护，完成自动及手工验证。

验收：

- 在实际 Windows 11＋Edge 或 Chrome 上按说明从干净虚拟环境启动；云环境检查不能代替 Windows 验证，未测试时明确记录。
- 使用至少三份有合法使用来源的 TI/ST/GD32 文字型手册，覆盖多栏文字、参数表、公式和图片；记录来源及版本，不擅自把第三方手册提交仓库。此项需要用户在 Windows 实机完成。
- 每份手册抽查至少 5 页，包含表格、公式或图片页，与原 PDF 视觉核对；页数、翻页、缩放和跳页正确，无明显缺失。
- 至少 10 个单页选区的文本、页序号与定位正确，缩放后再次定位仍正确；遇到错误阅读顺序能预览发现并提示，不声称支持复杂跨栏解析。
- 非 PDF、损坏文件、加密文件及无文字层样例有明确反馈，不崩溃；文件大小和页数上限在实现时公开并测试边界。
- 导入前后原件摘要一致；不覆写同名原件；关闭服务后可按说明重启。
- 无网仍可阅读已导入 PDF；没有任何 AI 请求。记录测试硬件，并以约 100 页样例首次可阅读不超过 5 秒、普通翻页不超过 1 秒为初始目标；未达标先记录并定位，不伪报通过。

### 阶段 2：专业选区翻译（约 4～6 天）

接入一个真实 AI 供应商，建立密钥设置、连接检查、选区发送预览、结构化译文、术语表和参数保真检查。先比较少量候选模型，再固定一个默认模型；供应商与模型费用以当时官方价格为准。

验收：

- Windows 本地使用有效密钥完成真实翻译，左原文右中文；没有密钥或断网仍可阅读。模拟响应只用于错误路径测试，不能代替真实接入验收。
- 建立至少 30 段人工核对样例，覆盖目标器件及正负数、指数、范围、μ/µ、Ω、°C、不等号、上下标、公式、表格表头和测试条件。
- 样例中每个关键参数及条件逐项核对；出现错误则修正，或被明确拦截/标为需核对，不能存在未标记的关键失真。术语表不能掩盖上下文差异。
- 用受控错误结果验证数值变更、单位遗漏、条件遗漏的警告；记录未覆盖的复杂情况，不能将测试样例通过等同于所有 PDF 保证正确。
- 无效密钥、超时、限流、取消、重复点击均可恢复；默认不自动无限重试。密钥不出现于前端、仓库或日志，正式保存走 Windows 凭据存储。
- 显示本次输入范围、模型与估算费用说明；供应商不返回用量时明确写“未知”。

### 阶段 3：解释、追问与可核对引用（约 3～5 天）

加入初学者解释、当前选区会话、真实证据编号与点击定位。解释可结合电机控制器场景，但不能把例子写成当前芯片规格。

验收：

- 至少 15 个问题覆盖术语、原理、参数条件与超出选区范围的问题；有文档依据的结论能回到正确文件和页面，引用片段支持结论。
- 至少 5 个证据不足问题明确提示范围不足；通用知识标注清楚，不编造页码、引用或器件参数。
- 切换文件后不会把上一份文档的选区作为新文件的证据；解释与忠实译文清晰区分。
- 进行至少 3 轮连续追问，支持取消和清空；文档中的恶意指令样例不会改变操作权限或泄露密钥。

### 阶段 4：第一版稳定性与 Windows 验收（约 3～5 天）

整合前三阶段，完善安全边界、错误反馈、启动说明与版本记录。交付可运行源码、固定依赖、Windows 启动脚本及新手操作手册；此阶段不要求独立安装包。

验收：

- 在一台未配置该项目的 Windows 11 机器或干净账户中，按说明完成安装、启动、AI 设置和完整阅读闭环，记录实际环境。
- 全部已有自动回归检查通过；完成真实 PDF＋真实 AI 的端到端操作。跳过、失败及人工未验证项分别记录。
- 连续阅读和翻译至少 30 分钟，切换至少 3 份文档，无未处理异常或会话串用；大文件限制、取消及重启有效。
- 本地 API 拒绝任意路径读取和不合法文档 ID，校验来源及写操作令牌，不使用通配跨域；富文本输出经过安全渲染，文件名和 AI 内容不能执行脚本。
- 原始文件保持不变，密钥及手册内容未泄露到日志；已知限制、数据目录和停止服务的方法写入说明。

阶段 1～4 粗估合计约 13～21 个专注工作日，首次接触 PDF 和 Windows 兼容问题时应保留额外缓冲。没有实际 Windows 和 AI 验证时，不能宣称 v0.1 已全面验收。

### 阶段 5：长期阅读数据（约 3～5 天）

SQLite 保存笔记、阅读位置、书签与翻译缓存；缓存键包含文档摘要、选区、上下文、模型、提示词和术语表版本。支持备份与导出，清理应用数据要明确确认。

验收：关闭重启后恢复笔记与位置；修改文档或模型后不误命中旧缓存；重复相同请求命中缓存且不发 API 请求；备份恢复成功；清理不触碰原始 PDF。

### 阶段 6：复杂文档与批量任务（按子项单独估算）

按实际需求依次做整页翻译、全文任务队列、OCR、全文证据检索。整页仍先采用原 PDF＋侧栏中文，不直接许诺中文版排版重建。OCR 及公式识别分别评测。

验收：长任务可取消、断点继续，显示预算及页级失败状态；扫描件至少 10 页人工核对并标记低可信参数；全文问答用预先标注证据的题集评测正确性和拒答；任何未经检查的批量结果不能标为已人工核实。

### 阶段 7：分发与可选本地模型

根据使用情况选择 Windows 桌面包装或 Python 打包；另行评估本地模型的硬件、中文术语质量与许可证。

验收：在没有 Python 开发环境的干净 Windows 机器验证安装、启动、升级和卸载；卸载前说明数据保留选项，不删除原始文件。本地模型模式断网完成实测，不能把仅本地界面称为离线 AI。

## 5. 技术难点、成本与应对

| 难点/成本 | 影响 | 处理方式 |
| --- | --- | --- |
| PDF 是绘图格式，文本顺序未必等于视觉顺序 | 多栏、表格、连字及公式容易乱码 | 先支持单页简单选区，显示预览；异常明确回退原文，后续评估结构识别 |
| 参数意义依赖条件和脚注 | 数字没变也可能翻译错含义 | 同时核对参数与条件关联；术语表、保护片段和人工评测共同使用 |
| 模型幻觉与错误引用 | 可能误导器件选型 | 引用只用真实记录；区分通用解释、原文结论与证据不足 |
| 密钥、文件与浏览器安全 | 本地服务仍有攻击面 | 只监听本机、同源限制、请求校验、最小文件权限、安全渲染、系统密钥存储 |
| Windows 与云端差异 | 路径、字体、凭据存储和启动脚本不同 | 云端做接口和自动测试；用户机器完成实际 Windows 验收，逐步给操作说明 |
| 大手册渲染与全文费用 | 内存占用、响应慢、费用上升 | 按需渲染和释放页面；限制上下文，后续缓存及批量预算控制 |
| 维护与许可证 | 升级可能破坏文字层或增加分发义务 | 固定 PDF.js/worker 版本、保留第三方许可清单、升级跑样例回归 |

基础开发工具和本地存储可使用免费开源方案；个人本地使用无需购买服务器。AI API 一般按 token（模型计费的文字片段）收取输入/输出费用，部分还有缓存或其他费用，订阅聊天产品通常不等于已有 API 额度。

预算计算：费用约等于 输入 token 数 ÷ 1,000,000 × 输入单价 ＋ 输出 token 数 ÷ 1,000,000 × 输出单价。示例仅为算术假设：100 次请求，每次 2,000 输入、1,000 输出 token，若价格分别是每百万 5 元与 20 元，则约 3 元；这不是任何供应商的实时报价或项目费用承诺。长会话、重试和全文翻译会增加费用。

阶段 1 无 AI 费用。阶段 2 再与用户确定供应商及小额试用预算，可先以 20～50 元作为人工预算上限；应用估算不等于供应商硬性限额，应同时配置账户预算或限额（若供应商支持）。真实 API 评测需要用户在本机安全配置密钥，不在聊天发送。OCR 与本地模型初期不购买服务或硬件，先用样例判断是否值得投入。

## 6. 测试证据与合作约定

- 自动测试重点：文件边界、参数校验、来源映射、错误处理；界面端到端重点：导入—选区—请求—引用跳转。
- 人工样例记录原文、页码、期待保留的参数和条件、实际结果及问题；硬件正确性无法仅靠程序断言，需回到原文核对。
- 每阶段交付注明：实现功能、运行步骤、实际测试平台、通过/失败/跳过情况、已知限制和下一步；不能把演示数据当作真实 AI 结果。
- 用户原始文件不得未经允许删除；不把密钥、个人笔记或无再分发授权的 PDF 推送到仓库。
- 当前仅修改规划文档，不修改或发布云环境配置。后续开发开始前不要求用户先选全套工具。

## 7. 下一次确认的具体内容

建议开始阶段 1：在 Windows 上可运行的最小 PDF 阅读器，范围是导入、原样阅读、翻页缩放、搜索、单页选区与定位。先不接 AI，也不做整页翻译、笔记和安装包。

用户确认后，再创建应用结构和运行说明、执行开发与测试。第一阶段结束时用户实际完成“打开一份常用手册、查找参数、选中一段英文并看到正确页码”的验收操作，然后共同进入阶段 2。
